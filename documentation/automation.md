# 自動化與代理邊界

## 代理說明

| 項目 | 當前實現 |
| --- | --- |
| 觸發 | 用戶顯式調用`$goutoujunshi`，或宿主根據Skill描述匹配相關請求 |
| 所有者 | 用戶控制當前任務；倉庫維護者維護公開指令 |
| 自動運行 | 只在Codex任務內響應，不存在後臺或定時運行 |
| 可讀輸入 | 當前對話，以及按需加載的倉庫Markdown文檔 |
| 必需工具 | 無 |
| 外部副作用 | 無；只生成建議文本 |
| 審批 | 現實發送、刪除、聯繫或求助動作均由用戶自行決定 |

## 提示詞引導與硬邊界

`SKILL.md`包含首次建檔、情緒支持、知識路由、建議格式和安全邊界。這些屬於模型引導，並非程序級強制控制。

真正的硬邊界來自宿主環境：模型安全政策、文件系統權限、網絡權限、工具參數校驗和用戶批准。倉庫不能聲稱僅靠提示詞徹底阻止越權或有害輸出。

## 輸出契約

常規回答應儘量包含：

1. 對用戶情緒和核心矛盾的準確回應。
2. 已知事實、合理推測和關鍵未知的區分。
3. 明確的首選建議及2–4個理由。
4. 必要時提供不同策略強度、話術和預期代價。
5. 一件下一步、觀察窗口或停止條件。

若信息不足，代理最多優先詢問會改變建議的關鍵問題；首次建檔例外，需要收集Skill規定的最小資料。

## 失敗處理

- 資料缺失：標註未知，不虛構。
- 資料矛盾：指出矛盾並請求糾正關鍵項。
- 高風險請求：拒絕危險操作部分，提供安全替代。
- 法律或醫療不確定：說明侷限，建議核對地區和諮詢合格專業人員。
- 工具不可用：繼續提供純文本支持，不假裝已執行外部操作。
